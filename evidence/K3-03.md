## Что сделано

Добавил запуск настоящих тестов в GitHub Actions. Проверил успешный запуск, затем специально изменил ожидаемый HTTP-статус в одном тесте, чтобы получить ошибку. После этого исправил тест и повторно проверил работу CI.

## Команды и результаты

```yaml

```

Коммит: `f64b4c9`.

## Проверка ошибки

В файле `tests/test_app.py` в методе `test_create_request` заменил:

```python
self.assertEqual(status, 201)
```

на:

```python
self.assertEqual(status, 200)
```

Приложение при успешном создании заявки возвращает HTTP-статус `201 Created`. Именно этот результат проверяет тест.

После изменения ожидаемого значения тест завершился с ошибкой:

```text
test_create_request ... FAIL
AssertionError: 201 != 200
Ran 7 tests
FAILED (failures=1)
```

Коммит с ошибкой: `cf4d2f0`.

[Красный запуск Student CI](https://github.com/ipsergei/DevOps-course/actions/runs/44545206515)

## Исправление

Вернул правильное ожидаемое значение `201` и отправил отдельный коммит.

Коммит с исправлением: `1aeb162`.

[Зелёный запуск Student CI](https://github.com/ipsergei/DevOps-course/actions/runs/44545663575)

После исправления все 7 тестов снова прошли успешно:

```text
Ran 7 tests
OK
```

## Ожидал

При неправильном ожидаемом статусе `200` тест `test_create_request` должен завершиться с ошибкой, а GitHub Actions показать красный результат. После возвращения `201` проверка должна пройти успешно.

## Получил

Прогноз подтвердился. С неправильным ожиданием один тест упал, а после исправления все 7 тестов прошли успешно.

## Почему это подтверждает результат

GitHub Actions действительно запускает тесты приложения и проверяет их результат. Если хотя бы один тест не проходит, команда завершается с ошибкой и весь job получает статус `Failure`.

## Ответ на вопрос из задания

Неверное ожидание теста тоже делает CI красным, потому что тест сравнивает фактический результат с ожидаемым. Если они не совпадают, возникает `AssertionError`, даже если само приложение работает правильно.
