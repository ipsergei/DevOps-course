# Работа K2-05

- **Группа:** ИТ-9.24.3-ДН
- **Код студента (без ФИО):** ipsergei

- **Что сделано:**

  В `compose.student.yaml` специально изменил `API_URL` у сервиса `web` с `http://api:8000` на `http://api:9999`. Проверил работу сайта и логи, после чего исправил порт обратно на `8000`.

- **Команды и существенный вывод:**

  ```bash
  docker compose -f compose.student.yaml up -d web
  docker compose -f compose.student.yaml logs --tail=40 web
  docker compose -f compose.student.yaml up -d web
  ```

  При неправильном порте сайт открывался, но список заявок был недоступен. При попытке отправить заявку появлялось сообщение «Сервис заявок недоступен».

  В логах обнаружил ошибку:

  ```text
  "event": "upstream_unavailable",
  "target": "http://api:9999",
  "error": "<urlopen error [Errno 111] Connection refused>"
  ```

  Также запрос `GET /api/requests` возвращал код `503`.

- **Ожидал:**

  При неправильном порте `9999` сервис `web` не сможет подключиться к `api`. После возвращения порта `8000` всё должно снова работать.

- **Получил:**

  При неправильной настройке список из 5 заявок не отображался, новые заявки не принимались.

  После исправления `API_URL` все 5 заявок снова появились. Создал новую заявку №6 («Не работает экран»), она успешно принялась.

- **Почему это подтверждает результат:**

  Причиной ошибки был неправильный порт в `API_URL`. Сам веб-сервис работал, но не мог подключиться к API. После исправления порта связь восстановилась.

- **Ошибка и её исправление:**

  Неправильная настройка: `API_URL=http://api:9999`.

  Исправленная настройка: `API_URL=http://api:8000`.

  После исправления повторно выполнил `docker compose -f compose.student.yaml up -d web`.

- **Ответ на вопрос из задания:**

  Между контейнерами нужен порт `8000`, потому что API слушает именно его. Порт `8080` используется для доступа к веб-интерфейсу с компьютера.
